# Contributing to Split

Welcome to Team Split!

This markdown document describes how our team plan to work together on Split. The practices below should be reviewed by the team before begin contributing and followed as works are being done. 

This guide may be updated as the project develops. 

## Team Norms

- Communicate respectfully.
- Raise and escalate blockers early on.
- Keep the project board up to date.
- Check in with team before taking over work; avoid redundant work.
- Always ask for help when needed!
- There are no "stupid" questions. 
- Share enough context when communicating. 
- Record contributions accurately. 
- Follow up, follow through, close the loop. 

## Sprint Planning and Stand-ups

- ... review the priorities

- Friday 
- Sunday. 

Meeting times and the team's final agreement are still to be confirmed. 
These times will be added here once agreed.

Each member shares:
- DID:      What they have completed since the previous stand-up.
- DOING:    What they plan to work on next.
- BLOCKERS: Any hurdles or help they need.

## Git Workflow

- Create a branch from the latest master in the team repository.
- Keep commits focused with single-line messages. 
- Push progress between stand-ups.
- Open a pull request to the team's master branch. Include the related issue and checks performed.
- Review with the team before merging, then update the board.

## Contributions

- Contributions include:
    - Code
    - Design 
    - Documentation 
    - Tests 
    - Research. 
- Check the board before starting and discuss scope changes with the team.
- Follow the existing code style and convention
- Cite all sources.
- Never commit secrets.
- Work is considered done when: 
    - Requirements are met 
    - Checks and review are complete
    - Result is merged
    - Changes are documented.
- Comply with all course policies.
